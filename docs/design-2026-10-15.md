# 手势地球 · 设计文档

日期：2026-10-15　状态：已确认（2026-10-15 由用户确认：拇指内收门控采用，拖拽方向采用抓取语义）
实施计划：`docs/plan-2026-10-15.md`
替代：本版推倒此前的 globe.gl 实现（视觉方向和控制模型都不对）

## 一、这是什么，为什么重做

一个纯前端网页：摄像头对着手，手在屏幕前直接操作一颗 3D 地球。跑在 iPad 的 Safari 里，iPad 自己当摄像头又当屏幕，手就伸在屏幕前面。

上一版有两处根本性错误，这版推倒重来。

第一，控制模型选错。上一版把手掌偏离画面中心的程度映射成"持续的旋转速度"，等于用手推一根摇杆——手不回正中心地球就一直转，停不下来。这一版改成位移拖拽：手的位移累加到角度上，手停住地球就停。

第二，视觉方向不对。上一版是卫星贴图的写实球加金色圆点，不是要的效果。这一版做全息玻璃壳加点阵内芯。

## 二、目标

1. 单手和双手都能操作，两种模式自动切换，用户不用记当前处在哪个模式。
2. 直接操纵：手的位移对应地球的角位移，手停住后地球在 0.3 秒内完全静止。
3. 缩放可以停在任意级别，不会因为手张开就被强行拉到某个固定距离。
4. 视觉为「全息玻璃壳 + 点阵内芯」。
5. iPad（第 10 代）横屏下稳定 60fps，至少连续五分钟不掉到 30fps 以下。
6. 手离开画面再回来，视角不跳变。
7. 首次打开时模型下载有明确进度，且只下载一次。

## 三、非目标（本期不做）

- 城市下钻：点开一座城市之后发生什么，留到下一期。
- 食指指向高亮城市（候选手势第 4 号，未选）。
- 五指张开一键复位（候选手势第 6 号，未选）。
- 写实卫星贴图、夜景灯光等其他视觉方向。
- 手机端适配，只保证 iPad 横屏和桌面 Chrome。
- 账号、云端存储、分享。
- 后端。整页静态，所有计算在浏览器内完成，画面不出设备。

## 四、反面目标（技术跑通了也算失败）

- 手停住之后地球还在缓慢转或漂移。
- 用户只是想拖拽，却因为手张开被判定成"比数字"而跳了视角。
- 手重新进入画面的一瞬间地球跳一下。
- 手势之间互相误触发，用户得小心翼翼才不出错。
- 打开页面后长时间黑屏没有反馈。
- iPad 发热后掉帧到手感崩坏。

## 五、约束

- 设备：iPad（第 10 代），Apple A14，4GB 内存，iPadOS 18.7.8，Safari。前置摄像头在长边，122 度超广角，需横屏使用。
- 不能用 WebGPU：iPadOS 18 的 Safari 没有默认开启，渲染和推理都走 WebGL2 加 WASM。
- 必须 HTTPS：Safari 只给安全上下文摄像头权限，本地 http 协议拿不到画面。最终部署到 Cloudflare Pages。
- 摄像头只在页面前台可用，切后台即断。
- 模型体积：MediaPipe HandLandmarker 的 task 文件 7.8MB，只有 Google 存储这一个官方来源，在部分网络下极慢。必须做持久缓存。

## 六、已经定下来的做法

### 6.1 技术栈

- 渲染：three.js 裸写，ESM 从 CDN 引入。不再使用 globe.gl。
- 识别：MediaPipe Tasks Vision 的 HandLandmarker，WASM 加 WebGL2 GPU 委托，numHands 设为 2（双手模式需要）。
- 构建：仍是单文件 index.html，无构建步骤，直接部署。

### 6.2 视觉：全息玻璃壳加点阵内芯

分层，从外到内：

| 层 | 做法 | 备注 |
|---|---|---|
| 星空背景 | 约 1800 个点，均匀分布在半径 70 的球面上 | 静态，不随地球旋转 |
| 玻璃壳 | 半径 1.0 的球，不透明度约 0.014 | 只是极淡一层膜，不能厚，厚了会把陆地粒子糊成雾 |
| 边缘辉光 | 菲涅尔壳，半径 1.05，强度约 0.7 | 提供"球在发光"的轮廓 |
| 经纬网 | 30 度间隔，青色，不透明度约 0.26 | 只保留一组，两组会显得脏 |
| 倾斜光环 | 3 道不同倾角与半径的发光圆环 | 半径 1.22 / 1.34 / 1.46 |
| 陆地点云 | 半径 0.978，在玻璃壳内部 | 约 46000 个斐波那契球面采样点，取陆地处，得约 13000 个点 |
| 城市 | 30 个金色发光点，半径 1.008，带柔和辉光精灵 | 鼠标悬停显示名字 |

关键实现细节：陆地点云必须用斐波那契球面采样，不能按经纬度铺格子。经纬格子在两极会退化成同心波纹，看起来像渲染 bug，上一版已经踩过这个坑。

所有视觉参数集中在文件顶部，方便调整。

### 6.3 手势

#### 共用基础

- 参考点：手腕、食指根、中指根、无名指根、小指根五个点的质心。这些是指关节，不随手指伸屈移动，所以既稳定又接近掌心的旋转中心。
- 尺度归一化：用手腕到中指根的距离作为手掌尺度，所有位移除以它再换算。这样把手凑近或拿远摄像头，灵敏度不变。
- 丢失恢复：连续 0.2 秒没有检测到手就判定离开，此时什么都不做，保持当前视角和距离。手回到画面时把那一帧记为新的基准，并做 0.15 秒的增益渐入，避免回来的瞬间把抖动当成拖拽。

#### 单手旋转

累加逐帧位移：每帧算出手掌参考点相对上一帧的位移量，乘以增益加到角度上。

- 横向位移映射到经度，纵向位移映射到纬度。
- 增益设成"手掌横跨画面一次约转 200 度"。
- 纬度限制在正负 80 度，避免翻过极点导致画面打结。
- 不加持续惯性，见下面的甩动规则。

#### 单手缩放（捏合）

相对映射，不是绝对映射。

1. 当拇指尖到食指尖的距离除以手掌尺度，低于 0.55 时进入捏合状态，记录当时的距离基准和当前高度。
2. 捏合期间高度等于基准高度乘以「基准距离除以当前距离」，即手指合拢一半就拉近一倍。
3. 比值回升到 0.85 以上才退出，滞回处理，避免在临界值反复横跳。
4. 退出后保持当前高度不动。

这样用户可以停在任意缩放级别，张开手掌不会把地球推走。

#### 新增手势 1：甩动惯性

- 维护一个速度估计，对最近约 6 帧的位移做滑动平均。
- 手停住的那一帧，如果速度超过阈值，就按该方向继续转动，速度按指数衰减，时间常数约 0.5 秒。
- 如果停止时速度低于阈值，立即停住，不产生任何滑行。

这条和目标里的"手停球停"不矛盾：慢速停下来是干脆的停，快速划过才有滑行，和刷手机列表的规则一致。

#### 新增手势 2：手指计数跳视角

伸出 1 / 2 / 3 / 4 根手指，分别跳到四个预设视角。

| 手指 | 视角 | 大致目标 |
|---|---|---|
| 1 | 亚洲 | 东经 105，北纬 25 |
| 2 | 欧洲 | 东经 15，北纬 50 |
| 3 | 美洲 | 西经 90，北纬 30 |
| 4 | 大洋洲 | 东经 145，南纬 25 |

触发条件，三条同时满足并保持 0.5 秒：

1. 伸直的手指数正好等于 1 到 4 中的某一个。
2. 拇指处于内收状态，即拇指尖到食指根的距离除以手掌尺度，低于约 0.9。
3. 手掌移动速度低于阈值。

第 2 条是必须的，用来区分"比数字"和"摊开手掌"。摊开手掌时拇指自然外展，距离偏大；比数字时拇指内收贴向掌心。没有这一条，用户拖拽完张开手静止半秒就会误触发跳视角。这一条是设计时定下的判断，属于实现方的决定，可以推翻。

命中后地球用约 0.8 秒缓动飞到目标视角，之后进入 0.6 秒冷却，避免连续触发。

#### 新增手势 3：掌心倾斜控制地轴

- 倾斜角来自「手腕到中指根」这个向量与画面竖直方向的夹角。
- 映射到地球的轴向倾斜，限制在正负 35 度。
- 平滑要比旋转更重，避免手抖导致地球晃。
- 这个角度只影响地球的轴朝向，不参与拖拽旋转。

#### 新增手势 5：双手模式

两只手同时出现在画面时自动进入，需要连续 3 帧都检测到两只手，避免边缘抖动导致模式反复切换。

- 缩放：用两手参考点的距离。同样是相对映射——进入双手模式时记录基准距离和基准高度，之后按比例缩放。两手同时向外拉是快速拉远，向内合是快速拉近。这条和单手捏合互补：捏合是精调，双手拉合是大幅跳转。
- 旋转：用两手连线方向的转动驱动地球旋转。
- 双手模式下，单手捏合和手指计数全部禁用，避免互相干扰。

#### 手势总表

| 手势 | 触发条件 | 效果 |
|---|---|---|
| 单手拖拽 | 一只手，且不满足其他条件 | 旋转 |
| 单手捏合 | 距离比低于 0.55 进入，高于 0.85 退出 | 缩放 |
| 手指计数 | 拇指内收加持平 1 到 4 根手指加静止 0.5 秒 | 跳视角 |
| 掌心倾斜 | 始终生效 | 地轴倾斜 |
| 甩动惯性 | 手停止时速度超过阈值 | 滑行后减速 |
| 双手拉合 | 两只手都在画面 | 大幅缩放 |
| 双手转动 | 两只手都在画面 | 旋转 |
| 手离开画面 | 0.2 秒无检测 | 冻结，保持现状 |

### 6.4 模型加载

- 同时向多个来源发起下载，5 秒后比谁传得多，留快的、掐掉慢的。来源顺序是同目录下的 hand_landmarker.task（部署时一起上传就从自己的站点分发），然后回落到 Google 存储。
- 用 Cache API 持久化，下载一次之后永久命中本地缓存。
- 20 秒没有任何新数据就判定断开，换源或者明确报错，不能无声挂起。
- 界面上分阶段显示当前在做什么，卡住时能一眼看出卡在哪一环。

## 七、留给实现者的空间

### 7.1 实现方已经定下的判断（请重点复核这几条）

写文档时以"接手实现的人"的视角把方案过了一遍，发现五处会导致返工的空白，先定下来：

1. **拖拽方向用抓取语义。** 手往右推，地球表面跟着往右走，也就是相机经度减小；手往上推，露出南半球。这和拖动地图、拖动手机的直觉一致。方向做成一个符号常量，觉得反了改一个正负号即可。

2. **桌面保留鼠标和触控操作。** 鼠标拖动旋转、滚轮缩放继续可用，用于桌面调试和演示。鼠标操作期间暂停手势接管约 1 秒，否则两边会互相抢相机。

3. **视角飞行可以被手势打断。** 跳视角的 0.8 秒缓动期间，如果用户开始拖拽，立即终止飞行并由手势接管。不做打断的话用户会觉得"卡住不动"。

4. **地轴倾斜作用在世界空间。** 改的是地球组的 Z 轴旋转，和经度、纬度完全解耦。如果把它做进相机空间，倾斜会和拖拽互相污染。

5. **横纵灵敏度必须按画面宽高比校正。** 位移先换算到像素域，再除以手掌尺度的像素值，否则 16:9 画面里纵向会比横向灵敏一大截。

- 各条平滑曲线、时间常数、阈值的具体数值，必须真机调手感。
- 甩动惯性的速度阈值和衰减常数。
- 城市点光晕精灵的生成参数。
- 检测是否放进 Worker。
- 城市列表是否需要扩充或替换。
- 增益渐入渐出、视角飞行缓动的具体实现方式。
- 渲染分辨率与设备像素比的取舍，iPad 是 2 倍屏，建议上限取 2。
- 帧率控制策略：渲染 60fps、检测 30fps、检测帧之间如何插值。

## 八、验收标准

1. iPad 横屏连续使用五分钟，帧率稳定在 30fps 以上，目标 60fps。
2. 手停住后地球在 0.3 秒内完全静止；快速划过时能看到惯性的滑行。
3. 缩放在任意级别都能停住，张开手掌不会改变距离。
4. 手移出画面再回来，视角不跳变。
5. 拖拽完张开手静止，不会触发跳视角。
6. 单手和双手之间来回切换，没有明显的突变或打架。
7. 模型第二次打开是秒进。
