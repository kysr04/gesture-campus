# 手势地球（重做版）实施计划

> **给执行者：** 必需子技能：superpowers:subagent-driven-development 或 superpowers:executing-plans，逐任务执行本计划。步骤用 `- [ ]` 勾选跟踪。

**目标：** 把 `index.html` 重做成「全息玻璃壳 + 点阵内芯」的视觉，并把控制模型从速度摇杆改成位移拖拽，加上甩动惯性、手指计数跳视角、掌心倾斜、双手模式。

**架构：** 单文件 `index.html`，无构建步骤。three.js 裸写渲染（不再用 globe.gl），MediaPipe Tasks Vision HandLandmarker 做手部检测。手势判定写成一组纯函数加一个状态机，与渲染解耦——这样可以在没有摄像头的情况下用合成关键点测出对错。

**技术栈：** three.js 0.160（ESM，CDN）、MediaPipe Tasks Vision 1.1.1（WASM + WebGL2）、Playwright（验证用，不是运行时依赖）。

**规格：** `docs/design-2026-10-15.md`（本计划的依据，执行时两份一起读）

## 全局约束

- 单文件交付，`index.html` 一个文件装下全部。不加构建步骤，不引入打包器。
- 运行环境：iPad（第 10 代）横屏 Safari；兼容桌面 Chrome。
- 不能用 WebGPU，只用 WebGL2 + WASM。
- 所有视觉和手势参数集中在文件顶部一个常量区，不得散落在代码各处。
- 渲染分辨率上限：`min(devicePixelRatio, 2)`。
- 摄像头画面不出设备，不引入任何后端调用。
- 全部依赖走 CDN，且每个依赖要有备用源。
- 本项目当前不是 git 仓库。任务里的提交步骤在初始化仓库后才执行，见任务 0。

```js
// ---- 手势判定（纯函数，输入归一化关键点 0..1，不碰 DOM、不碰 three.js）----

// 手掌参考点与尺度。ref 是 0..1 归一化坐标，scale 是归一化长度。
palmRef(lm) -> { ref: {x, y}, scale: number }

// 手部姿态。extended 是食指/中指/无名指/小指中伸直的根数（0..4）。
// thumbIn 是拇指是否内收。pinch 是指距除以手掌尺度的比值。
fingerState(lm) -> { extended: 0..4, thumbIn: boolean, pinch: number }

// 倾斜角，弧度，来自「手腕→中指根」与画面竖直方向的夹角。
palmTilt(lm) -> number

// ---- 手势状态机 ----

const engine = createGestureEngine(constants)

// hands: 长度 0..2 的数组，每项是 21 个 {x,y} 归一化关键点
// 返回一份控制指令，渲染层只读它，不反推手势
engine.update(hands, nowMs) -> {
  mode: 'idle' | 'rotate' | 'pinch' | 'twoHand' | 'jumping',
  yaw: number,          // 目标经度，度
  pitch: number,        // 目标纬度，度
  altitude: number,     // 目标高度，地球半径的倍数
  tiltZ: number,        // 地轴倾斜，弧度
  jumpedTo: string|null // 本帧触发跳转的目标名，null 表示没触发
}

engine.reset()          // 清空基准、速度、冷却，用于手丢失恢复

// ---- 场景 ----

createScene(container) -> {
  apply(cmd, dt),       // 把控制指令套用到地球与相机
  resize(),
  dispose()
}

// ---- 调试钩子（仅在网址带 ?debug 时挂上）----
window.__gesture = { reset, step, state, constants }
```

```js
// 造一只合成的手，坐标是 MediaPipe 那套 0..1 归一化图像坐标。
// ext: 长度 4，对应食指/中指/无名指/小指是否伸直
// thumbTip: 拇指尖位置，用来控制内收与外展、以及和食指的捏合距离
function makeHand({ ext = [1, 1, 1, 1], thumbTip, cx = 0.5, cy = 0.55 } = {}) {
  const lm = Array.from({ length: 21 }, () => ({ x: cx, y: cy }));
  lm[0] = { x: cx, y: cy + 0.15 };            // 手腕
  const mcpX = [cx - 0.07, cx - 0.025, cx + 0.02, cx + 0.065];
  [5, 9, 13, 17].forEach((id, i) => { lm[id] = { x: mcpX[i], y: cy }; });
  [6, 10, 14, 18].forEach((id, i) => { lm[id] = { x: mcpX[i], y: cy - 0.09 }; });
  [8, 12, 16, 20].forEach((id, i) => {
    lm[id] = { x: mcpX[i], y: ext[i] ? cy - 0.22 : cy - 0.045 };
  });
  lm[1] = { x: cx - 0.09, y: cy + 0.08 };
  lm[2] = { x: cx - 0.115, y: cy + 0.045 };
  lm[3] = { x: cx - 0.13, y: cy + 0.02 };
  lm[4] = thumbTip || { x: cx - 0.15, y: cy + 0.01 };   // 默认内收
  return lm;
}

const POSE = {
  open: () => makeHand({ thumbTip: { x: 0.22, y: 0.58 } }),               // 五指张开，拇指外展
  counting: (n) => makeHand({                                            // 比数字，拇指内收
    ext: [1, 1, 1, 1].map((_, i) => (i < n ? 1 : 0)),
    thumbTip: { x: 0.35, y: 0.56 }
  }),
  pinch: () => makeHand({                                                // 捏合：拇指尖贴住食指尖
    ext: [1, 1, 1, 1],
    thumbTip: { x: 0.423, y: 0.35 }
  })
};

module.exports = { makeHand, POSE };
```

自检：`POSE.open()` 的拇指尖到食指根(5) 的距离约为 0.21，除以手掌尺度 0.152 得 1.4（外展）；
`POSE.counting(2)` 得 0.53（内收）。

- [ ] **步骤 3：实现判定函数**

在 `index.html` 的 module 里加常量区与判定区。关键代码：

```js
const HAND = {
  WRIST: 0, THUMB_TIP: 4, INDEX_MCP: 5, MIDDLE_MCP: 9,
  PALM_IDS: [0, 5, 9, 13, 17],
  FINGERS: [[8, 6], [12, 10], [16, 14], [20, 18]],  // [指尖, 第二关节]
  EXTEND_RATIO: 1.06,
  THUMB_IN_RATIO: 0.9
};

const d2 = (a, b) => Math.hypot(a.x - b.x, a.y - b.y);

/** 掌心的质心与手掌尺度。用的是掌指关节，不受手指伸屈影响。 */
function palmRef(lm) {
  let x = 0, y = 0;
  for (const i of HAND.PALM_IDS) { x += lm[i].x; y += lm[i].y; }
  const n = HAND.PALM_IDS.length;
  return { ref: { x: x / n, y: y / n }, scale: d2(lm[HAND.WRIST], lm[HAND.MIDDLE_MCP]) || 1e-6 };
}

function fingerState(lm) {
  const wrist = lm[HAND.WRIST];
  let extended = 0;
  for (const [tipId, pipId] of HAND.FINGERS) {
    if (d2(lm[tipId], wrist) > d2(lm[pipId], wrist) * HAND.EXTEND_RATIO) extended++;
  }
  const { scale } = palmRef(lm);
  return {
    extended,
    thumbIn: d2(lm[HAND.THUMB_TIP], lm[HAND.INDEX_MCP]) / scale < HAND.THUMB_IN_RATIO,
    pinch: d2(lm[HAND.THUMB_TIP], lm[8]) / scale
  };
}

/** 倾斜角：手腕到中指根的向量与画面竖直方向的夹角，弧度。 */
function palmTilt(lm) {
  const dx = lm[HAND.MIDDLE_MCP].x - lm[HAND.WRIST].x;
  const dy = lm[HAND.MIDDLE_MCP].y - lm[HAND.WRIST].y;
  return Math.atan2(dx, -dy);
}
```

同时在调试钩子里加 `probe(lm)`，返回 `{ ...palmRef(lm), ...fingerState(lm), tilt: palmTilt(lm) }`。

- [ ] **步骤 2：实现陆地点云，必须用斐波那契球面采样**

这是上一版踩过坑的地方——按经纬度铺格子在两极会退化成同心波纹，看起来像渲染 bug。

```js
/**
 * 陆地点云。先按斐波那契球面铺均匀的点，再逐个回查陆地遮罩。
 * 不要改成按经纬度循环，两极一定会出现同心波纹。
 */
async function landGeometry(count, radius) {
  const tex = await loadTexture(EARTH_TEXTURE_URL);
  const W = 1440, H = 720;
  const c = document.createElement("canvas");
  c.width = W; c.height = H;
  const ctx = c.getContext("2d", { willReadFrequently: true });
  ctx.drawImage(tex.image, 0, 0, W, H);
  const d = ctx.getImageData(0, 0, W, H).data;
  const pos = [];
  const golden = Math.PI * (3 - Math.sqrt(5));
  for (let i = 0; i < count; i++) {
    const yy = 1 - (i / (count - 1)) * 2;
    const rad = Math.sqrt(Math.max(0, 1 - yy * yy));
    const th = golden * i;
    const xx = rad * Math.cos(th);
    const zz = rad * Math.sin(th);
    const lat = Math.asin(yy) * 180 / Math.PI;
    const lon = Math.atan2(xx, zz) * 180 / Math.PI;
    const px = Math.min(W - 1, Math.max(0, Math.floor((lon + 180) / 360 * W)));
    const py = Math.min(H - 1, Math.max(0, Math.floor((90 - lat) / 180 * H)));
    const k = (py * W + px) * 4;
    if (d[k + 2] - d[k] > 20 && d[k + 2] - d[k + 1] > 12) continue;   // 海洋
    pos.push(xx * radius, yy * radius, zz * radius);
  }
  const g = new THREE.BufferGeometry();
  g.setAttribute("position", new THREE.Float32BufferAttribute(pos, 3));
  return g;
}
```

无需光照，点云是自发光材质。

- [ ] **步骤 3：按设计文档 6.2 的表格搭出其余各层**

严格照表实现。三处容易做坏的地方：

1. **玻璃壳的不透明度必须留在 0.014 附近。** 调高到 0.05 就会在整个轮廓上糊一层白雾，把陆地粒子盖住——上一版渲染过一版这样的废图。
2. **经纬网只保留一组**（30 度间隔）。再叠一组更密的会显得脏。
3. **菲涅尔壳用加法混合且 `depthWrite: false`**，否则会挡住后面的点云。

```js
// 换算到像素域再除以手掌尺度的像素值，保证横纵灵敏度一致
const dxPx = (ref.x - prev.ref.x) * frameW;
const dyPx = (ref.y - prev.ref.y) * frameH;
const scalePx = prev.scale * frameW;

// 死区消抖：没超过这个位移就当作手没动
const DZ = GESTURE.DEADZONE_PX;          // 建议 1.5
if (Math.hypot(dxPx, dyPx) > DZ) {
  // 抓取语义：手往右，相机经度减小
  yaw   -= (dxPx / scalePx) * GESTURE.YAW_GAIN;
  pitch += (dyPx / scalePx) * GESTURE.PITCH_GAIN;   // 手往上推露出南半球
  pitch = clamp(pitch, -GESTURE.PITCH_LIMIT, GESTURE.PITCH_LIMIT);
}
```

`YAW_GAIN` 取 200 度，即横跨画面一次约转 200 度；`PITCH_LIMIT` 取 80 度。

- [ ] **步骤 3：实现甩动惯性**

```js
// 最近 6 帧的位移做滑动平均，得到速度（度/秒）
flick.push({ yaw: yawDelta, pitch: pitchDelta, dt });
if (flick.length > 6) flick.shift();

// 手停止的那一帧
if (movedThisFrame === false && !coasting) {
  const avg = averageFlick(flick);
  if (Math.hypot(avg.yaw, avg.pitch) > GESTURE.FLICK_MIN) {
    coastV = avg;                       // 进入滑行
    coasting = true;
  } else {
    flick.length = 0;                   // 慢速停止：干脆地停
  }
}

// 滑行期间，速度按指数衰减，低于阈值就彻底停
if (coasting) {
  const k = Math.exp(-dt / GESTURE.FLICK_TAU);   // FLICK_TAU 取 0.5 秒
  yaw += coastV.yaw * dt;
  pitch = clamp(pitch + coastV.pitch * dt, -GESTURE.PITCH_LIMIT, GESTURE.PITCH_LIMIT);
  coastV.yaw *= k; coastV.pitch *= k;
  if (Math.hypot(coastV.yaw, coastV.pitch) < GESTURE.FLICK_MIN) coasting = false;
}
```

新手势一介入（检测到位移超过死区）就立刻 `coasting = false; coastV = null;`，不允许惯性和拖拽打架。

### 执行中的偏离（都记录在案）

1. **平移参考点从"五个掌关节质心"改成"手腕"。**
   文档原话是质心。实测发现手腕侧倾时质心会跟着摆动，一个全幅侧倾会带出约 8 度
   意外旋转——也就是"倾斜地轴"这个手势会顺带把地球转走。手腕是侧倾的支点，
   转手腕它不动，正好解耦。这比字面照抄文档里的配方更贴合文档写的意图
   （"接近掌心的旋转中心"）。设计文档 6.3 已同步。

2. **旋转增益的数值和单位改了。** 原定 `YAW_GAIN: 200`，但那个数没有单位，
   实现时才发现它会被手掌尺度除——按原值手掌扫过半个画面要转 1300 度，完全没法用。
   现在单位明确为"每移动一个手掌宽度转多少度"，取值 `YAW_GAIN: 60` / `PITCH_GAIN: 40`。

3. **`engine.update` 的签名比计划多两个参数。** 实现需要帧率与画面尺寸：
   `update(hands, nowMs, dtOverride)`，另加 `setFrame(w, h)`。计划里写的是
   `update(hands, nowMs)`。

4. **`render.cjs` 的三角形上限从 2000 改成 20000。** 原数字是拍脑袋定的，忘了
   玻璃壳、菲涅尔壳和三个光环都是实体几何。三角形数本来也不是瓶颈，填充率才是。

5. **任务 8（模型竞速加载）在任务 2 的重写里就做掉了。** 因为旧的顺序加载版本
   正是导致"进度条一动不动"的那个 bug，不能留着它过夜。任务 8 的验证步骤照常做了。

6. **捏合测试改成渐进式。** 原来一帧之内从张开跳到捏紧，滤波器第一个采样就等于
   最终值，基准与当前值相等，缩放不会有任何反应——这是测试不真实，不是实现有问题。
   加了 `POSE.pinchRamp(t)` 模拟真实捏合过程。

7. **鼠标暂缓手势的机制补上了。** 设计文档 7.1 第 2 条要求鼠标操作暂停手势接管一秒，
   第一遍实现时漏了，后补。

8. **验证脚本共用一个浏览器配置目录，不能并行跑。** 并行会撞配置目录锁。
   串行执行即可。
